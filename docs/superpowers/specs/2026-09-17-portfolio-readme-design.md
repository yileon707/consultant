# 惠聚生活作品集 README 设计说明

## 目标

把 GitHub 仓库从“源码展示”提升为面向招聘面试官的项目作品页，让访问者在 30 秒内理解产品用途、真实运行效果和工程实现能力。

## 品牌调整

- 所有用户可见的产品名称统一为“惠聚生活”。
- 页面标题、侧栏品牌、AI 顾问称呼、欢迎语、免责声明、系统提示词和 README 标题同步更新。
- Java 包名、仓库名 `consultant`、数据库表名和接口路径保持不变，避免影响已有运行逻辑。

## README 展示结构

1. 项目标题与一句话定位：本地生活 AI 顾问，连接商家、优惠券与到店预约。
2. 首屏产品截图：展示惠聚生活的主聊天页面和本地生活快捷入口。
3. 面试官关注的能力卡片：流式对话、RAG 检索、工具调用、Redis 会话记忆、MySQL 业务数据。
4. 功能截图：至少展示商家/优惠券查询和预约场景的真实对话结果。
5. 架构图：浏览器 → Spring Boot → LangChain4j → 阿里云百炼，并标出 RAG、Redis、MySQL 和业务工具。
6. 技术栈、运行方式、环境变量说明和安全说明。
7. 验证信息：构建/测试命令及当前验证结论。

## 图片资产

- 图片全部来自当前项目的真实运行页面或项目架构，不使用与项目无关的装饰素材。
- 图片放在 `docs/assets/`，文件名使用英文，README 使用相对路径引用。
- 不在图片中展示 API Key、数据库密码、手机号、用户数据或其他本地敏感信息。
- README 控制在 3–4 张核心图片，避免信息过载。

## 验收标准

- README 首屏能快速说明项目定位和完成效果。
- README 中的截图能在 GitHub 正常加载，桌面和移动端至少有一张真实界面证据。
- 项目源码中用户可见品牌统一使用“惠聚生活”和“惠聚顾问”。
- `mvn -q test` 通过，且脱敏规则继续排除 SQL、构建产物和本地配置。
